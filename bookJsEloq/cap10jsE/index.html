JAVASCRIPT CAP10

MODULOS

En la practica los programas crecen de forma organica, se agregan piezas funcionales segun las necesidades.

PROGRAMAS MODULARES

Un modulo es un parte del programa que especifica en que otras piezas se basa y que funcionalidad proporciona par que otros modulos las utilicen (su interfaz).

Las interfaces de modulos se parecen a las interfaces de objetos. Permite que una parte del modulo este disponible para el mundo exterior y mantiene el resto en privado.

Pero la interfaz de un modulo para que otros las utilicen es solo la mitad de la historia, un buen sistema de modulos requiere que los modulos especifiquen que codigo ellos utilizan de otros modulos. Estas relaciones se llaman dependencias. Cuando estas dependencias se especifican claramente en el propio modulo se pueden utilizar para averiguar que otros modulos deben estar presentes para poder utilizar un modulo dado y cargar las dependencias automaticamente.

Cuando las formas en que los modulos interactuan entre si son explicitas, un sistema se vuelve mas como un LEGO donde las piezas interactuan a traves de conectores bien definidos.

MODULOS ES("ECMAScript")

Javacript admite dos tipos diferentes de programas.

  • Los scripts: sus vinculadores se definen en el ambito global y no tiene forma de referencias directamente a otro script.
  • Los modulos: obtienen su propio ambito separado y admiten las palabras claves import y export que no estan en los scrips para declarar sus dependencias e interfaz

Un programa modular esta compuesto por varios modulos, conectados a traves de sus importaciones y exportaciones. 

// ARCHIVO JS.JS
let names = ["Domingo", "Lunes", "Martes", "Miércoles","Jueves", "Viernes", "Sábado"]
export function dayName(number) {
    return names[number]
}

export function dayNumber(name){
    return names.indexOf(name)
}

// ARCHIVO OTRO.JS
import {dayName} from "./js.js"
let hoy = new Date();
console.log(`Hoy es ${dayName(hoy.getDay())}`) // → Hoy es domingo

La palabra clave exports se puede colocar delante de la funcion, clase o definicion de vinculacion para indicar que esa vinculacion es parte de la intefaz del modulo. Esto permite que otros modulos utilicen esta vinculacion importandola.

La palabra import, seguida de una lista de nombres de vinculacion entre llaves {}, hace que las vinculaciones de otro modulo esten disponibles en el modulo actual. Los modulos se identifican por cadenas entre comillas.

Para ejecutar un modulo se carga todos los modulos en los que depende, y las vinculaciones exportadas se ponen a disposicion de los modulos que lo importan.

Las declaraciones de importacion y exportacion no pueden estar dentro de funciones, bucles u otros bloques.

Así que la interfaz de un módulo consiste en una colección de vinculaciones con nombres, ala cuales tiene acceso otros modulos que dependen de ellas. Es decir, cuando pongo delante de las funciones la palabra export se crean estas "colecciones de viculaciones" que seran ocupados por otros mudulos.

Las viculaciones importadas se pueden renombar para darles un nuevo nombre local utilizando as despues de su nombre.

import {dayName as nomDeJour} from "./dayname.js";

Tambien es posible que un modulo tenga una exportacion especial llamda default, que amenudo se usa para modulo que solo exportan un solo enlace. Para defir una exportacion predeteminada se escribe export dfault antes de una expresion, una declaracion de funcion o una declaracion de clase.

export default ["Invierno", "Primavera", "Verano", "Otoño"]
import nombresEstaciones from "./nombrsestaciones.js"

PAQUETES

Un paquete es un fragmento de codigo que se puede distribuir (copiar e instalar).

Cuando se encuentra un problema en un paquete o se añade una nueva caracteristica, se actualiza el paquete ahora los programas que dependen de el pueden copiar la nueva version para obtener las mejoras que se hicieron en el codigo.

Trabajar de esta manera requiere infraestructura. Necesitamos un lugar para almacenar y encontrar paquetes y una forma conveniente de instalr y actualizarlos.

En el Javascrip esta infraestructura es prevista por NPM.

NPM es dos cosas: un servicio en linea donde puedes descargar ( y subir ) paquetes y un programa (incluido con Node.js) que te ayuda a instalar y gestionarlos.
