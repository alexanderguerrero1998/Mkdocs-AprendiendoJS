JAVASCRIPT CAP20

Node.js es un entorno de ejecucion que permite que javascript se interprete fuera del navegador es decir en el servidor y fue creado para resolver un problema concreto: manejar muchas conexiones de red al mismo tiempo.

Las tenologias tradiciones (como apache con PHP) creaban un hilo nuevo por cada conexcion. Si llegaban 10.000 usuarios al mismo tiempo, necesitaban 10.000 hilos lo cual consumia mucha memoria

Node.js resolvio esto con la programación asincrónica, donde un solo hilo permite al programa realizar varias conexiones/tareas a la vez sin bloquearse esperando que una termine para comenzar la siguiente.

JavaScript fue el lenguaje ideal para esto porque, al no tener un sistema propio de manejo de entrada y salida, pudo adaptarse perfectamente al modelo de Node sin generar conflictos. En resumen, Node.js convierte a JavaScript en una herramienta poderosa para sistemas en red porque no espera, sino que reacciona.

EL COMANDO NODE

Cuando Node.js esta instalado, proporciona el comando node para ejecutar archivos JavaScript desde la linea de comandos. El metodo console.log funciona igual que el navegador, pero en lugar de mostrar el resultado en la consola del navegador, lo imprime en la terminal.

Ademas todas las funciones estandar de JavaScript como Array, Math o JSON estan disponibles en Node, pero no las propias del navegador como document o prompt

MODULOS

Node.js soporta dos sistemas de modulos: el tradicional CommonJS, que usa require y funciona con archivos .js. Y el modenos ES Modules, que se usa import y export y funciona con archivos .mjs

Cuando se importa un archivo, Node resuelve esa ruta de tres formas. si comienza con ./, ../ o / lo busca como un archivo local; si no tiene esa forma, lo busca como un módulo integrado de Node o dentro de la carpeta node_modules.

INSTALANDO CON NPM

NPM cumple dos papeles, es un repositorio en linea de modulos JavaScript que viene instalado junto con Node.js y a la vez es una herramienta que permite descargar e instalar paquetes. Al ejecutar npm install seguido del nombre de un paquete, npm lo descarga y crea una carpeta llamada node_modules en el directirio actual, donde guarda el codigo de ese paquete para que pueda ser usado en el proyecto.

Una caracteristica importante de NOM es que instala los paquetes localmente en cada proyecto y no en un lugar centralizado del sistema. Esto permite que cada proyecto tenga sus propias dependencias.

ARCHIVOS DE PAQUETE

Despues de ejecutar npm install para instalar algun paquete, no solo te creara un directorio node_modules, sino tambien un archivo llamdao package.json en tu directorio actual. Se recomienda tener este ultimo archivo en cada proyecto ya que contiene informacion basica del proyecto como us nombre, version y descripcion, pero lo mas importante es que registra todas las dependencias , es edcir, los paquetes externos que el proyecto necesita para funcionar. js { "name": "prueba", { "name": "prueba", "version": "1.0.0", "description": "", "version": "1.0.0", "description": "", "description": "", "main": "index.js", "main": "index.js", "scripts": { "scripts": { "test": "echo \"Error: no test specified\" && exit 1" "test": "echo \"Error: no test specified\" && exit 1" }, "keywords": [], "author": "", "license": "ISC", "type": "commonjs" }

VERSIONES

Un archivo pakage.json lista tanto la version del propio programa como las versiones de sus dependecias.

NPM utiliza el versionado semantico para gestionar la compatibilidad entre paquetes. Una version semantica consiste en tres numeros, separados por puntos, como 2.3.0. Cada vez que se añade una nueva funcionalidad el numero de en medio cambia (esto no rompe la antigua interfaz). Pero cuando el primer numero cambia rompe la compatibilidad con versiones anteriores (esto si rompe la antigua interfaz).

El caracter de intercalacion ^ delante del numero de version indica que se puede instalar cualquier version con el numero dado, por ejemplo ^2.3.0 permite instalar cualquier versión mayor o igual 2.3.0 y menor que 3.0.0.

npm permite a los desarrolladores publicar sus propios paquetes usando npm publish, simpre que el nombre del paquete no este ya en uso.

EL MODULO DEL SISTEMA DE ARCHIVOS

El modulo node:fs es el sistema de archivos de Node.js y permite leer, escribir y manipular archivos desde el codigo. La funcion readFile lee un archivo y luego llama a una funcion con el contenido del archivo, y requiere especificar la codificacion utf-8 para descodificar el archivo en una cadena. Si no pasas una codificacion, Node asumira que estas interesado en datos binarios y te dara un objeto Buffer en lugar de una cadena. Este es similar a un array que contiene numero que representan los bytes.

import {readFile} from "node:fs"
readFile("texto.txt","utf-8",(error, texto) => {
    if(error) throw error
    console.log(texto)
})
// → Esto es un texto de puebas. 

// Cuando no especificas la codificacion obtienes esto:

<Buffer 45 73 74 6f 20 65 73 20 75 6e 20 74 65 78 74 6f 20 64 65 20 70 75 65 62 61 73 2e 20>

La writeFile se utiliza para escribir un archivo en el disco y asume utf-8 por defecto cuando recibe el texto. Y ademas sobre escribe el archivo desde cero.

writeFile recibe tres argumentos:

  • La ruta del archivo (obligatorio): dónde guardar el archivo.
  • El contenido (obligatorio): la cadena de texto o Buffer que quieres escribir.
  • Un callback (obligatorio en la versión con callbacks): función que se ejecuta cuando termina, recibiendo un error si algo salió mal.
import {writeFile} from 'node:fs'
writeFile("texto.txt","Node estuvo aqui!", (err)=>{
    if(err) console.log(err)
    else console.log("Archivo escito")
}) // → Node estuvo aqui!

El módulo node:fs contiene muchas otras funciones utiles:

  • readdir te dará los archivos en un directorio como un array de cadenas,
  • stat recuperará información sobre un archivo,
  • rename cambiará el nombre de un archivo,
  • unlink lo eliminará, entre otros.

Node ofre tres formas de trabajar con archivos:

  • Usando callbacks con node:fs
  • Usando promesas node:fs/promises ```js import {readFile} from 'node:fs/promises'

readFile("texto.txt","utf-8") .then((text)=> console.log(text)) - Usando versiones Sincronas como `readFileSync` que detiene completamente el programa mientras se ejecuta.js import {readFileSync} from "node:fs"; console.log("El archivo contiene:", readFileSync("texto.txt", "utf8"));

```

EL MODULO HTTP

El modulo node:http permite crear un servidor HTTP con pocas lineas de codigo usando createServer, esta funcion recibe como parametro un call =back que se ejecuta cada vez que un cliente hace una solicitud, el callback recibe dos objetos: solicitud (request) que contiene informacion de la URL solicitada, y una respuesta(response) que sirve para mandar la respuesta al cliente.

Esto es todo lo que se necesita para iniciar un servidor HTTP.

import {createServer} from 'node:http'
createServer((solicitud, respuesta)=>{
      respuesta.writeHead(200,{"content-type":"text/html"})
      respuesta.write(`Hola! Solicitaste esto:${solicitud.url}`)
      respuesta.end()
}).listen(8000) 
// → Hola! Solicitaste esto: /

Para responder se usan tres pasos: writeHead para enviar codigo de estado ( 200 para OK) y un obbjeto que contiene los encabezados content-type para indicar que estamos enviando de vuelta un archivo HTML, write para enviar el contenido (el documento en si) y end para cerrar la respuesta. La llamada a server.listen permite escucjar conexiones en el puerto 8000.

FLUJOS

En Node.js, el objeto response de un servidor HTTP es un flujo de escritura (Writable Stream). Esto significa que puedes enviar datos poco a poco usando write() y cerrar la comunicación con end().

También puedes crear flujos de escritura hacia archivos con createWriteStream del módulo node:fs,lo que permite escribir archivos por partes.

Por otro lado, el objeto request es un flujo legible (Readable Stream). En lugar de usar métodos para leer, se trabaja con eventos. En Node, los objetos que emiten eventos usan on(nombreEvento, funcion) para reaccionar cuando algo ocurre.

Los streams legibles tienen principalmente dos eventos importantes:

  • data → se ejecuta cada vez que llegan datos.

  • end → se ejecuta cuando ya no hay más datos.

Esto es ideal para datos que llegan en partes, como una solicitud HTTP o un archivo grande.

Un flujo legible (Readable Stream) es un objeto que produce datos por partes (chunks) a lo largo del tiempo, en lugar de entregar todo de una sola vez.

Un flujo escribible (Writable Stream) es un objeto al que se le pueden enviar datos por partes.

Este codigo crea un servidor que lee los cuerpos de las solicitudes y los reenvia al cliente como texto en mayusculas.

import {createServer} from "node:http";

createServer((solicitud, respuesta) => {
    respuesta.writeHead(200, {"Content-Type": "text/plain"});
    solicitud.on("data", fragmento => respuesta.write(fragmento.toString().toUpperCase()));
    solicitud.on("end", () => respuesta.end());
}).listen(8000, ()=> console.log("Servidor escuchando en el pueto 8000"));

Recuerda que desde el navegador solo se pueden hacer peticiones GET

Para hacer peticiones desde la consola se ocupa esto:

curl.exe -X POST http://localhost:8000 -d "Hola Mundo"
// → Hola Mundo

Para hacer peticiones desde el navegador

fetch("http://localhost:8000/", {
    method: "POST",
    body: "Hola Mundo!"
})
.then(respuesta_O_Response => respuesta_O_Response.text())
.then(x => console.log(x))
// → Hola Mundo!

UN SERVIDOR DE ARCHIVOS

Utilizaremos un objeto llamado methods para almacenar las funciones que manejan los diferentes métodos HTTP. Los controladores de métodos son funciones async que reciben el objeto de solicitud como argumento y devuelven una promesa que se resuelve a un objeto que describe la respuesta.

import { error } from "node:console";
import {createServer} from "node:http"
import {metodos} from "./metodos.js"


import "./methodGET.js"
import "./methodPUT.js"
import "./methodDELETE.js"
import "./methodMKCOL.js"


createServer((req, resp)=>{

    let handler = metodos[req.method] || notAllowed;

    handler(req).catch(error => 
    {
        if (error.status != null) return error;
        return { body: String(error), status: 500 };

    }).then(( {body, status = 200, type = "text/plain"}) => 
    {
        resp.writeHead(status, {"Content-Type": type});
        if (body && body.pipe) body.pipe(resp);
        else resp.end(body);

    });

}).listen(8000,()=>console.log("Servidor escuchando en el puerto 8000 ..."))

async function notAllowed(req) {
    return {
        status:405,
        body : `Metodo ${req.method} no permitido`
    }
}

Esto inicia un servidor que simplemente devuelve respuestas de error 405, que es el código utilizado para indicar que el servidor se niega a manejar un método determinado.

Para determinar quw ruta de archivo corresponde a un URL de solicitud, la funcio urlRuta utiliza la clase integrada URL para analizar la URL. Este constructor espera un url completa, no solo la parte diagonal que obtenemos con resquest.url, por lo que proporcionamos un nombre de dominio falso para completar http://d. Extraer su ruta, se sera algo como "/archivo.txt", la decodifica para eliminar los codigos de escape estilo %20 y la resuelve en relacion con el directorio de trabajo dle programa.

El objeto URL es una herramienta del navegador y de Node.js que descompone una dirección web en piezas claras.

Recibe dos argumentos: Una url (Obligatorio) y base (opcional, solo necesario si el primer argumento es un URL relativa)

Sus propiedades principales son:

  • href: es la URL completa:
    https://www.ejemplo.com:8080/productos/camiseta?id=15&color=rojo#info
  • protocol: el protocolo que usa la página: http - https - ftp
  • hostname: el dominio del sitio: www.ejemplo.com
  • port: el puerto usado por el servidor: 8080
  • host: Es la combinacion del hostname + puerto: www.ejemplo.com:8080
  • pathname: Es la ruta dentro del servidor: /productos/camiseta
  • search: son parametros de consulta:?id=15&color=rojo
  • searchParams: Es un objeto especial para leer parámetros fácilmente: direccion.searchParams.get("id")
import {parse} from "node:url"
import {resolve, sep} from "node:path"

const directorioBase =  process.cwd();

function urlRuta(url){
    let {pathname} = new URL(url,"http://d");
    let ruta = resolve(decodeURIComponent(pathname).slice(1));
    if(ruta != directorioBase && !ruta.startsWith(directorioBase + sep))
    {
        throw {status:405, body:"Prohibido"};
    }
    return ruta;
}

process.cwd() (donde cwd significa “directorio de trabajo actual”) devuelve: el directorio donde se está ejecutando el programa. Ejm 

C:\Users\alexa\OneDrive\Escritorio\sis_files>

Ese sera el límite del servidor. El programa solo permitirá acceder a archivos dentro de esa carpeta.

resolve() convierte la ruta en una ruta absoluta del sistema. Ejemplo:

Si el servidor corre en: 
/home/alex/mi-servidor

Y el usuario pide: 
/imagenes/foto.png

resolve() genera:
/home/alex/mi-servidor/imagenes/foto.png

Aquí es exactamente donde ocurre lo que decía el texto: "resolver la ruta respecto al directorio de trabajo del programa"

Porque está usando el directorio actual del programa como base.

decodeURIComponent(pathname) convirte los codigos de escape.

sep representa el separador de carpetas del sistema operativo. devuelve automáticamente el correcto dependiendo del sistema donde corre el programa.

import {createReadStream} from "node:fs"
import {stat, readdir} from "node:fs/promises"
import {lookup} from "mime-types"

import {metodos} from "./metodos.js"
import {urlRuta} from "./urlRuta.js"


metodos.GET = async function (req) {
    let ruta = urlRuta(req.url);
    let stats;
    try{
        stats = await stat(ruta)

    } catch (error){
        if(error.code != "ENOENT") throw error
        else return {status:404, body: "Archivo no encontrado"};
    }
    if(stats.isDirectory()) {
        return {body: (await readdir(ruta)).join("\n")};
    } else {
        return {body: createReadStream(ruta), type: lookup(ruta) || "application/octet-stream"}
    }

};

stat Sirve para obtener información de cualquier cosa en el sistema de archivos, y lanza un error cuando no puede obtener esa informacion.

El sistema responde con un objeto llamado Stats. Este objeto contiene información como: si es archivo, si es carpeta, tamaño, fecha de creación, fecha de modificación, permisos

Stats {
  size: 2048,
  mtime: 2026-03-06,
  ...
}

Internamente el objeto Stats tiene metodos utilies: stats.isFile() stats.isDirectory() stats.isSymbolicLink().

error.code permite identifica el tipo de error. Puede vale: ENOENT (archivo no existe) EACCES (permiso denegado) EEXIST (el archivo ya existe)

function pipeStream(from, to){
    return new Promise((resolve, reject) => {
        from.on("error", reject);
        to.on("error", reject);
        to.on("finish",resolve)
        from.pipe(to)
    });
}

PREGUNTAS

¿Que tiene que ver Node.js con npm?

Node.js es un entorno de ejecucion de JavaScript en el servidor. NPM es el gestor de paquetesde Node.js

¿Que tiene que ver un entorno de ejecicion con un gestor de paquetes?

Cuando escribes codigo en Node.js casi siempre necestas librerias externas. Alguien tiene que descargarlas, versionalas y organizarlas. Para eso existe npm.

Es como la relacion entre:

  • Python(entorno) y pip (gestor de paquetes)
  • Java (entorno) y Maven (gestor de paquetes)

Cada lenguaje/entorno casi siempre trae sus propio gestor de paquetes, no porque sean lo mismo, sino por que sin el, el entorno seria poco practico.

¿ Osea si yo instalo node tambien se instala npm ?

Sí, exactamente. Al instalar Node.js, npm se instala automáticamente junto con él.

¿Entonce cada entorno de ejecucion debe tener un gestor de paquetes? ¿Porque?

Cuando desarrollas software, rara vez escribes todo desde cero. Usas código que otros ya escribieron (librerías).

¿De dónde descargo esa librería? ¿Qué versión uso? ¿Qué pasa si esa librería necesita otras librerías? ¿Cómo comparto las dependencias de mi proyecto con otro desarrollador?

Sin un gestor de paquetes tendrías que hacer todo eso a mano, lo cual es tedioso y propenso a errores.

No es que un entorno de ejecucion necesite un gestor de paquetes para funcionar si no que el desarrollador lo necesita para trabajar de forma comoda y organizada. Por eso siempre aparecen juntos.

¿Cual es la diferencia de un entorno de desarrollo y de un entorno de ejecucion y cuales son sus siglas ?

Entorno de Ejecución (Runtime Environment)

Siglas: RE (o en inglés Runtime)

Es donde el código corre/se ejecuta. Es el ambiente que interpreta y procesa tu código cuando ya está listo para funcionar.

  • Ejemplo: Node.js ejecuta JavaScript en el servidor

Entorno de Desarrollo (Development Environment)

Siglas: DE (o en inglés Dev Environment) Es donde el desarrollador escribe y prueba el código. Incluye todas las herramientas necesarias para programar.

  • Editor de código (VS Code)
  • Librerías de prueba
  • Herramientas de depuración (debugger)
  • etc.

¿Que tiene que ver nodejs con el el servidor?

Antes de Node.js, JavaScript solo podia correr en el navegador. No podias usarlo para programar la logica de un servidor.

¿Qué significa eso?

Que con Node.js puedes usar JavaScript para:

  • Recibir peticiones de usuarios
  • Conectarte a una base de datos
  • Devolver respuestas
  • Leer archivos del sistema

Cosas que antes solo podías hacer con lenguajes como Java, PHP o Python.

¿Aque te refieres con que node.js permite correr JavaScript en el servidor ? es decir, ¿Cual es la diferencia de que JavaScript corra en el servidor o en el navegador ?

Cuando JavaScript corre en el navegador, tiene acceso a cosas del navegador como:

  • El HTML de la página
  • Los botones y formularios
  • Las cookies
  • La pantalla del usuario

Pero no puede tocar el sistema operativo, leer archivos, ni conectase directamente a una base dedaos.

En el servidor: cuando JavaScript corre en el servidor con Node.js, tiene acceso a cosas del sistema como:

  • Archivos del disco
  • Base de datos
  • Red
  • Memoria del sistema

Pero no tiene navegador, ni pantalla, ni HTML que manipular.

Es el mismo lenguaje (JavaScript), pero dependiendo de dónde corre, tiene acceso a cosas distintas y cumple roles distintos.

¿Qué pasa si quiero usar módulo ES sin package.json?

  • Node no reconocerá import/export hasta que declares "type": "module"en package.json.

Pregunta: ¿Para qué sirve npm init -y?

  • Crea un package.json con valores por defecto. Sin -y, Node te hace preguntas interactivas.

Promesas y fetch

  • Async y Promesas: Toda función async devuelve una Promesa.

  • .then() recibe el valor con el que se resolvió la Promesa.

  • .catch() atrapa errores de la función async o de la Promesa.

  • Estados de Promesas: pending, fulfilled, rejected.

  • En fetch, la Promesa se resuelve con un objeto Response que contiene status, ok, headers, text(), json().

  • Los números (o valores primitivos) devueltos por Promesas normales no tienen propiedades como status o body, esas son propias de Response en HTTP.

Diferencia entre conceptos

  • resolve() → función de Promesas que entrega el valor de resolución.

  • response → objeto HTTP que representa la respuesta de un servidor.

  • Async no crea status ni body, eso depende del objeto que devuelvas.

  • En fetch, Response tiene esas propiedades porque así lo diseñó la API, no por ser async.

Reglas prácticas que se desprenden

  • Async = Promesa garantizada.

  • Handler async permite manejar cualquier operación demorada sin cambiar la estructura del servidor.

  • .then() recibe exactamente el valor que resolve() entrega.

  • .catch() solo funciona si la función async lanza un error o la Promesa se rechaza.
