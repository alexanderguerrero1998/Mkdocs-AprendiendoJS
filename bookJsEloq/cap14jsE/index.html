ESTRUCTURA DEL DOCUMENTO

Un documento HTML es como un conjunto anidado de cajas (etiquetas).

Para cada caja hay un objeto con el que podemos interactuar para saber cosas como que etiqueta HTML representa o que cajas y textos contiene.

Esta representacion se llama Modelo de Objetos del Documento, o DOM en resumen.

El enlace global document nos da acceso a estos objetos(cajas). Su propiedad documentElement hace referencia al objeto que representa la etiqueta <html>

ARBOLES

Llamamos arbol a una estructura de datos cuando tiene una estructura de remificaciones y tiene una raiz unica y bien definida. En el caso del DOM document.documentElement sirve como la raiz.

Un arbol tipico tiene diferentes tipos de nodos.Los nodos de aplicacion pueden tener hijos, mientras que los identificadores y valores son nodos hojas o nodos sin hijos.

Lo mismo ocurren en el DOM. Los nodos de los elementos que representan etiquetas HTML determinan la estructura del documento. Estos pueden tener nodos hijos. Ejemplo de dicho nodo es document.body. Algunos de estos hijos pueden ser nodo hoja, como fragmentos de texto o comentarios

Cada objeto de nodo del DOM tiene una propiedad nodeType que contiene un codigo que identifica el tipo de nodo.

  • Los elementos HTML tiene el codigo 1 que se define como la propiedad constante Node.ELEMENT_NODE
  • Los nodos de texto obtiene el codigo 3 (Node.TEXT_NODE)
  • Los comentarios tienen el codigo 8 (Node.COMMENT_NODE)

MOVIMIENTOS ATRAVES DEL ARBOL

Cada nodo tiene un propiedad parentNode que apunta al nodo del que forma parte, si lo hay. De igual manera, cada nodo del elemento (tipo1) tiene una propiedad childNodes que apunta a un objeto similar a un array que contiene sus nodos hijos.

Con esto podrias movere por todo el arbol utilizando estos enlaces pradre e hijo. Pero JS te da otros enlaces. Ejm. firsChil y lastChild apuntan a los primeros y ultimos elementos hijos o tiene un valor null para cada nodo sin hijos. previousSibling y nextSibling apuntan a nodos adyacente, es decir nodos que tienen el mismo padre (o que estan al mismo nivel (o nodos hermanos))

  • nextSiblig Devuelve el siguiente nodo hermano del nodo actual (cualquier nodo, ejm. nodos de texto o culaquier otra cosa).
  • previousSibling Es exactamente lo opuesto de nextSibling. Devuelve el nodo hermano anterior al nodo actual (cualquier nodo,ejm. nodos de texto o cualquier otra cosa).
  • nextElementSibling Siempre devuelve el siguiente elemente HTML ignirando nodos de Texto. (Solo elementos HTML)
  • previousElementSibling Devuelve el nodo hermano anterior al nodo actual (Solo elementos HTML)
  • childNodes Devuelve todos los nodos hijos sin excepción, incluyendo: Elementos HTML (tipo 1) Nodos de texto / espacios (tipo 3) Comentarios (tipo 8)
  • children Devuelve solo los hijos que son elementos HTML(Tipo 1), ignorando textos y comentarios.

ENCONTRANDO ELEMENTOS

Todos los nodos de elemento tiene un metodo getElementByTagname que recoje todos los elementos con el nombre de la etiqueta dada y que son descendientes (hijos directos o indirectos) de ese nodo y los devuelve como ub objeto similar a un array.

     let documento = document getElementsByClassName('main_container')
    console.log(documento) // Imprime todos los elementos que coicidan con la clase.
    // En este caso existen 2 elementos que tiene la misma clase y ademas son nodos hermanos. Es decir, 
    // son dos nodos que deben estar la mismo nivel para que puedan ser reconocidos por la funcion getElementsByClassName().
    // Similar funcionan con otras funciones semejantes.   

    // HTMLCollection(2) [div.main_container, div.main_container]
    //0: div.main_container ← Hermano 1
    //1: div.main_container ← Hermanos 2
    //length: 2

    //Ahora para poder ver los nodos hijos de estos elementos:
    /* 1. En este caso como tenemos 2 elementos de la misma clase('main_container'), debemos seleccionar de que
    elemento queremos ver sus nodos hijos. Ahora como  la funcion getElementsByClassName()
    devuelve un array de los elementos coicidentes, tenemos que ocupar notacion de un array para acceder 
    a cualquiera de estos dos elementos. Ejm. [0][1] ...
    1. Utilizamos la palabra reservada children para acceder a sus hijos

    */
    let documento = document.getElementsByClassName('main_container')[0] // ← Paso 1, accedemos a primer elemento del array y,  
    console.log(documento.children) // Seleccionamos todos sus hinjos

    // 0: div.child_container |

    // 2: a.EnlancaDirecto    |
    // length: 3                 ← Numero de nodos hijos


    // Si quisieramos acceder a un nodo hijo en especifico de un elemento,

    let documento = document.getElementsByClassName('main_container')[0]
    console.log(documento.children[0]) // → esto accede a div.child_container

CAMBIANDO EL DOCUMENTO

Los nodos tiene un metodo remove para removerlos de su padre actual.

Para añadir un nodo podemos usar appendChild que lo coloca al final de la lista de hijos

O insertBefore que inserta el primer nodo dado como primer argumento antes del segundo nodo dado como segundo argumento .

El motodo replaceChild se usa para remplazar un nodo hijo con otro. Toma como argumento dos nodos, un nodo nuevo y el nodo que se remplazara. replaceChild te permite cambiar un hijo por otro, pero debes llamarlo desde el padre del nodo que quieres reemplazar.

  padre.replaceChild(nodoNuevo, nodoAReemplazar);

  // Esto me permite por ejemplo si ese nodo tiene 
  // un id y quiesiera cambiar/actualizar a otro nodo pero que tenga el mismo id.

CREACION DE NODOS

Array.from() sirve para crear un array real a partir de algo que no es exactamente un array, pero que se parece… o que se puede recorrer.

    // EJM.1
    const divs = document.querySelectorAll("div")
    console.log(Array.isArray(divs)) // false

    const arrayDivs = Array.from(divs)
    console.log(Array.isArray(arrayDivs)) // true
    // Ahora puedes usar .map(), .filter(), .reduce() sin problema.

    // EJM.2 CASO ESPECIAL (Este es un tipo de Array-like)
    // El ejemplo funciona por que cumple con dos reglas claves
    // 1. Tiene Propiedades numericas [0][1]...
    // 2. Tiene una propiedad .lenght
    // Esto es suficiente para que Array.from() lo trate como un array             

    let arrayish = {0: "uno", 1: "dos", length: 2};
    let array = Array.from(arrayish);
    console.log(array.map(s => s.toUpperCase())); // → ["UNO", "DOS"]
    //⚠️ Pero ojo
    //Si el objeto no tiene length, no funciona. Porque no sabe cuantos elementos leer.                

    // 📌 Diferencia importante
    { nombre: "Alex", edad: 25 } //← Objeto Normal
    // No es array-like.
    // No tiene índices numéricos ni length.
    // Por lo tanto:
    Array.from({ nombre: "Alex" })
    // []

    // 🚀 Entonces… ¿cómo lo conviertes en array?
    // Si quieres un array con los valores
    // Object.values(data) → ["Alex", 25, "Ecuador"]
    //Si quieres un array con las claves
    // Object.keys(data) → ["nombre", "edad", "pais"]
    // Si quieres clave + valor (muy poderoso)
    // Object.entries(data) → [ ["nombre", "Alex"],["edad", 25],["pais", "Ecuador"] ]

    // EJM.3 CONVERTIR STRING EN ARRAY
    Array.from("Alex")
    // → ["A", "l", "e", "x"]

Para crear nodos puedes utilizar el metodo document.createElement Es metodo toma el nombre de la etiqueta y devuelve un nodo vacio del tipo dato.

ATRIBUTOS

Cuando estás trabajando con el DOM en JavaScript, algunos atributos HTML se pueden leer directamente como propiedades del objeto del elemento - ```js // Propiedades regulares
elemento.id elemento.className elemento.href elemento.src elemento.value

// Pero si creas un atributo personalizado
// (uno que tú inventas), el navegador no lo
// conoce y por lo tanto no lo convierte en
// propiedad del objeto

<div id="caja" color-favorito="azul"></div>
const caja = document.getElementById("caja");

caja.color-favorito   // ❌ No existe como propiedad regular
caja.id               // ✅ "caja" (propiedad regular, sí existe)
```
  • HTML te permite establecer cualquier atributo que desees en los nodos. Para leer o cambiar atributos personalizados que no estan disponibles como propiedades regualares del objeto, debes usar los metodos getAttribute y setAttribute
  • setAttribute recibe dos parametros, el primero el nombre del atributo y el segundo el valor de ese atributo
  //Utilizando setAttribute
  `<img id="imagen">`

  let documento  = document.getElementById('imagen')
  documento.setAttribute("src","./miFoto.png")
  // Esto crea un atributo src junto con su respectivo valor, en la etiqueta img.

getAttribute recibe un parametro, es decir el noombre del atributp que desea leer.

  let documento  = document.getElementById('imagen')
  documento.setAttribute("src","./miFoto.png")
  console.log(documento.getAttribute("src"))
  // ./miFoto.png ← Imprime el valor del atributo  
  ``` 
Se recomienda prefijar estos nombres de atributos con __data__ para evitar conflictos con otros atributos. Ejm. `data-recurso`

Para acceder a la clase del elemento se usa __className__. 
Esto tambien se prodia hacer con __getAttribute__. La diferencia 
esta en que la primera es solo para clases y el segundo es para cualquier propiedad en general.

__classList__ es una propiedad que te da acceso  a las clases de un elemento,
pero en lugar de darte un string te da un objeto con metodos para agregar,
quitar y manipular clases facilmente. Sus metodos son:

add() → Agrega una o varias clases. remove() → Elimina una o varias clases. toggle() → Agrega la clase si no existe, la elimina si ya existe. replace() → Reemplaza una clase por otra. contains() → Verifica si la clase existe.



## TIPOS DE COLECCIONES
### COLECCIONES VIVAS
Son aquellas que se actualizan automaticamente cuando el Dom cambia.
Métodos que devuelven colección viva:

document.getElementsByClassName() document.getElementsByTagName() document.getElementsByName() element.getElementsByClassName() element.getElementsByTagName()

Y este caso especial:

element.childNodes → devuelve un NodeList vivo element.children → devuelve HTMLCollection viva ```

COLECCIONES ESTATICAS

Son aquellas que no cambiar aunque el DOM cambie despues. Métodos que devuelven colección estatica: document.querySelectorAll() element.querySelectorAll()

PORQUE IMPORTA?

Esto es util de entender porque: mientras estas iterando una coleccion viva, modificas el DOM, la coleccion cambia mientras la recorres y eso altera el indice.

RESUMEN PRACTICO

  • Colección viva + solo lectura → ✔️ seguro ( No genera efectos secundarios que alteren tu lógica.)
  • Colección viva + mutación del mismo conjunto → ⚠️ riesgo
  • Colección estática + mutación → ✔️ predecible ( El comportamiento no cambia inesperadamente mientras lo recorres.)

Si vas a modificar la estructura que estas recorriendo trabaja con una copia estatica, si solo inspeccionas no hay drama. ```js // EJM.1 // Esto modifica la clase de todos los elementos de la misma clase // Pasan de verde a azul let change = document.querySelectorAll('.verde') for(let x of change) { x.className = "Azul" console.log(x) }

//EMP.2
// Esto no funciona porque getElementsByClassName devuelve
// una coleccion viva y si cambias un elemento de la clase verde a azul
// este se sale de la coleccion actual(porque ya cambio de clase) por ende,
//  ya no formaria parte de esa coleccion y esto supondria que haya menos 
// elementos en la coleccion y que los indices que estaban asociados a los elementos cambien
// como consecuencia de que se eliminan elementos al cambiar de clase. 
let change =  document.getElementsByClassName('verde')
for(let x = 0; x < change.length; x++)
{
    change[x].classList.replace('verde','azul')
    console.log(change[x])

}

```

POSICIONAMIENTO Y ANIMACION

La propiedad de estilo position tiene diferentes valores: * static el elemento se situa en su lugar normal del documento. * relative el elemento sigeu ocupando espacio en el documento pero ahora las propiedades top y left se pueden usar para moverlo con respecto a ese lugar * absolute El elemento se elimina del flujo normal del documento, ya no ocupa espacio y puede superponerse con otros elementos, se puede usar top y left

RESUMEN

El DOM es una estructura que representa el modelo del documento del navegador, y un programa en JavaScript puede modificarlo. El DOM esta organizado como un arbol,en el cual sus elementos estan ubicados jerarquicamente deacuerdo a la estructura del documento. Los elementos tiene propiedades como parentNode y childNodes que se usan para nevegar a traves de alrbol.
