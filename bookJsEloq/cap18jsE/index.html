JAVASCRIPT

El Protocolo de Trasnferenecia de Hipertecto es el mecanismo por el cual se solicita y proporciona datos a la World Wide Web.

EL PROTOCOLO

Cuando se envia una URL el navegador primero busca la direccion del servidor asociado con la URL e intenta abrir una conexion TCP con el puerto 80. Si el servidor existe y acepta la conexion se envia algo como esto 

GET /18_http.html HTTP/1.1
Host: eloquentjavascript.net
User-Agent: Nombre de tu navegador

Luego el servidor responde atravez de esa misma conexion

HTTP/1.1 200 OK
Content-Length: 87320
Content-Type: text/html
Last-Modified: Vie, 13 Oct 2023 10:05:41 GMT

<!doctype html>
... el resto del documento

El navegador toma la parte de la respuesta de la linea en blanco, su cuerpo y lo muestra como documento HTML.

Explicacion de la solicitud

  • La primera palabra es el metodo de la solicitud. GET significa que queremos obtener un recurso especificado.

  • La parte despues del nombre del metodo es la ruta del recurso que se solicita.

  • Despues de la ruta del recurso se menciona HTTP/1.1 para indicar la version del protocolo.

  • Luego viene la cabecera que son lineas en forma nombre : valor que se especifican informacion adicional de la solicitud

Explicacion de la respuesta

  • La respuesta del servido comenzara con una version del protocolo, seguida del codigo de estado de la respuesta

  • Los codigos de estado que comienzan con el numero 2 indican que la solicitu tuvo exito. Ejm. el codigo 200.

  • Los codigos que comienzan con 4 significa que hubo problemas con la solicitud. Ejm el 404 que significa que el recurso no se pudo encontrar.

  • Los que comienzan con 5 indican que ocurrio un error en el servidor y la solicitud no es la responsable.

  • Luego viene la cabecera que son lineas en forma nombre : valor que se especifican informacion adicional de la respuesta

Despues de las cabecerasm tanto las solucitudes como las respuestas pueden incluir una linea en blanco seguida del cuerpo que contiene el documento real que se envia.

NAVEGADORES Y HTTP

<form method="GET" action="example/message.html">
    <p>Nombre: <input type="text" name="name"></p>
    <p>Mensaje:<br><textarea name="message"></textarea></p>
    <p><button type="submit">Enviar</button></p>
</form>

Enviar un formulario significa que el contenido de sus campos se empaquetan en una solicitud HTTP. 

GET /example/message.html?name=Jean&message=Yes%3F HTTP/1.1

El signo de ? indica el final de la parte de la ruta de la URL y el inicio de la consulta. Le siguen pares de nombres y valores correspondientes al atributo name en los elementos del campo del formulario y al contenido de esos elementos respectivamente. Un carácter ampersand (&) se utiliza para separar los pares

En el ejemplo anterior si cambiamos al metodo POST, este colocara la cadena de consulta en el cuerpo de la solicitud, en lugar de agregarla a la URL.

POST /example/message.html HTTP/1.1
Content-length: 24
Content-type: application/x-www-form-urlencoded
name=Jean&message=Yes%3F

FECTCH

La interfaz a travez de la cual JavaScript del navegador puede hacer solicitudes HTTP se llama fetch

fetch("ejemplo/datos.txt").then(response => {
console.log(response.status);
// → 200
console.log(response.headers.get("Content-Type"));
// → text/plain
});

Cuando se llama a la fecth esta devuelve una promesa. Esa promesa, cuando se resuelve, entrega un objeto de tipo Response que contiene informacion sobre la respuesta del servidor, como su codigo de estado y sus encabezados. Los encabezados estan envueltos en un objeto similar a un Map como insensibles a mayusculas y minusculas.

fetch devuelve: Una Promesa → que resuelve en un objeto Response → que contiene:

  • status ← Esto permite conocer los estados (codigos) del servidor (Ejm 200,400), es decir sus respuestas. Las Promesas tienen otros estados que no son numericos (Mientras espera → pending, Si termina bien → fulfilled, Si falla la red → rejected). No confundir estados de promesas con las del servidor.
  • ok
  • headers
  • json()
  • text()

Concidera que la promesa que devuelve fetch se resuelve con exito incluso si el servidor responde con un codigo de error. La promesa puede ser rechazada su hay un error de response o si el servidor no se puede encontrar.

El primer argumento de fecth es la URL que se debe solicitar. Cuando esa URL no comienza con un nombre de protocolo (como http) se trata como relativa, es decir se interpreta en relacion con el documento actual.

El segundo algumento es un objetos de opciones donde puedes configurar cosas como el método (method), el cuerpo (body), los encabezados (headers), entre otros.

El segundo argumento es opcional, si no lo pasas, fetch hace una solicitud GET por defecto.

Para acceder al contenido de una respuesta puedes usar el metodo text

fetch("ejemplo/datos.txt")
.then(resp => resp.text())
.then(text => console.log(text));
// → Este es el contenido de datos.txt

Un metodo similar llamado json devuelve una promesa cuyo valor es el cuerpo del JSON, o se puede rechazar si no es un JSON valido.

Por defecto, fetch utiliza el metodo GET para la solicitud y no incluye un cuerpo de solicitud. Pero puedes agregarlo y para ello puedes incluir una opcion body. Para establecer cabeceras, esta la opcion headers. Por ejemplo, esta solicitud incluye una cabecera Range, que indica al servidor que devuelva solo una parte de un documento.

fetch("ejemplo/datos.txt", {headers: {Range: "bytes=8-19"}})
.then(resp => resp.text())
.then(console.log);
// → el contenido

Añadir tus propias cabeceras es muchas veces útil para incluir cosas como información de autenticación o para indicar al servidor en qué formato de archivo te gustaría recibir.

AISLAMIENTO HTTP

Hacer solicitudes HTTP desde scripts en páginas web genera riesgos de seguridad, porque el dueño del sitio podría usar tu navegador para enviar peticiones a otros dominios sin tu consentimiento (por ejemplo, a un banco usando tu sesión activa).

Para evitar esto, los navegadores aplican una política de seguridad que bloquea las solicitudes entre distintos dominios. Es decir, un script de un sitio no puede hacer peticiones libremente a otro dominio.

Sin embargo, cuando el acceso entre dominios es legítimo, los servidores pueden permitirlo enviando una cabecera especial en la respuesta, como:

Access-Control-Allow-Origin: *

Esto indica al navegador que sí se permite el acceso desde otros dominios (en este caso, desde cualquiera).

ARECIANDO HTTP

Cuando un programa en el navegador (cliente) necesita comunicarse con un servidor, existen distintas formas de organizar esa comunicación.

Una forma común es el modelo de llamadas a procedimientos remotos (RPC). Funciona como si llamaras a una función normal, pero en realidad se ejecuta en el servidor. El navegador envía el nombre de la función y sus argumentos, y el servidor responde con el resultado. En este modelo, HTTP es solo el “mensajero”, y suele esconderse detrás de una capa de abstracción.

El otro enfoque se basa en recursos y métodos HTTP. En vez de llamar a algo como addUser, se usa una solicitud como PUT /usuarios/larry. Los datos se envían en formato JSON dentro del cuerpo de la petición. Para obtener información, se usa GET /usuarios/larry, y el servidor devuelve el documento que representa ese recurso.

Este segundo enfoque aprovecha mejor las características propias de HTTP, como la caché, y usa principios bien diseñados del protocolo para estructurar la API del servidor de forma más sólida y escalable.

CAMPOS DE FORMULARIO

Los formularios nacieron en la Web antes de JavaScript, con la idea de enviar datos del usuario al servidor mediante una solicitud HTTP, normalmente cargando una nueva página.

Pero hoy los formularios forman parte del DOM como cualquier otro elemento. Eso significa que JavaScript puede leer, modificar y controlar sus campos gracias a sus propiedades y eventos especiales. Así, los formularios ya no solo envían datos: también pueden convertirse en piezas clave dentro de una aplicación dinámica en el navegador.

Un formulario se define con la etiqueta <form> y puede contener distintos tipos de campos: casillas, menús desplegables, campos de texto, entre otros. Muchos de estos campos usan la etiqueta <input>, y el atributo type determina el tipo de campo

Existen varios tipos comunes de :

  • text: campo de texto de una sola línea.

  • password: igual que text, pero oculta lo que se escribe.

  • checkbox: interruptor de encendido/apagado.

  • color: selector de color.

  • date: selector de fecha.

  • radio: opción dentro de un grupo de selección múltiple.

  • file: permite elegir un archivo desde la computadora.

Importante: los campos no tienen que estar dentro de una etiqueta <form>. Pueden colocarse en cualquier parte del HTML.

Eso sí, solo un <form> completo puede enviarse al servidor. Pero cuando trabajamos con JavaScript moderno, muchas veces no queremos enviar el formulario de forma tradicional, sino capturar y manejar los datos directamente desde el navegador.

CAMPOS DEHABILITADOS

Todos los campos de formulario pueden ser deshabilitados a través de su atributo disabled. Es un atributo que se puede especificar sin valor; el simple hecho de que esté presente deshabilita el elemento

<button disabled>Estoy fuera</button>

EL FORMULARIO EN SU TOTALIDAD

Cuando un campo está dentro de un <form>, su elemento DOM tiene una propiedad form que apunta al formulario al que pertenece.

Por su parte, el elemento <form> tiene una propiedad llamada elements, que contiene una colección con todos los campos que están dentro del formulario.

El atributo name de cada campo es clave porque:

  • Define cómo se identificará su valor cuando se envíe el formulario.

  • Permite acceder a ese campo desde form.elements usando su nombre.

La colección elements funciona de dos maneras:

  • Como un array (acceso por índice numérico).

  • Como un mapa (acceso por nombre del campo).

En otras palabras, el name no es solo decorativo: es la etiqueta operativa que conecta el frontend con el procesamiento de datos.

CAMPOS DE TEXTO

Todos tienen una propiedad value, que contiene el texto actual del campo como una cadena. Si cambias esa propiedad desde JavaScript, cambias directamente el contenido visible del campo.

CAMPOS DE SELECCION

Los campos <select> permiten elegir opciones, igual que los botones de radio. La diferencia es que con radio tú controlas más el diseño, mientras que el aspecto de <select> lo define el navegador.

Un <select> normal permite elegir una sola opción y suele mostrarse como lista desplegable.

Si se añade el atributo multiple, el usuario puede seleccionar varias opciones. En este caso, el campo muestra varias opciones al mismo tiempo, más parecido a un conjunto de casillas de verificación.

Cada <option> tiene un valor:

  • Puede definirse con el atributo value.

  • Si no se define, el texto visible dentro de la opción se usa como valor.

La propiedad value del <select> devuelve la opción seleccionada. Pero en un <select multiple>, esta propiedad solo devuelve uno de los valores seleccionados, por lo que no es muy útil por sí sola.

Para trabajar correctamente con múltiples selecciones:

  • Se usa la propiedad options, que es como un array con todas las opciones.

  • Cada opción tiene una propiedad selected, que indica si está seleccionada.

  • Esta propiedad también puede modificarse desde JavaScript para seleccionar o deseleccionar opciones programáticamente.

En resumen: <select> es una herramienta flexible, y con multiple se convierte en un control de selección masiva totalmente manejable desde código.

CAMPOS DE ARCHIVO

Los campos <input type="file"> fueron creados para subir archivos al servidor mediante formularios. Pero en navegadores modernos también permiten leer esos archivos desde JavaScript.

Un script no puede leer archivos del usuario por sí solo. Solo cuando el usuario selecciona manualmente un archivo, el navegador permite que el código lo lea.

<input type="file">

let input = document.querySelector("input");
input.addEventListener("change", () => {
    if (input.files.length > 0) {
    let file = input.files[0];
    console.log("Has elegido", file.name);
    if (file.type) console.log("Tiene tipo", file.type);
    }
});
// Has elegido HOJA DE VIDA.pdf

La propiedad files del campo contiene los archivos seleccionados. Es una colección similar a un array (no es un array real). Inicialmente esta vacio.

Aparte de file tambien existe un atributo multiple que permite seleccionar varios archivos al mismo tiempo

Los objetos en files tienen propiedades como name (nombre del archivo) size (tamaño del archivo en bytes) y type (el tipo de medio del archivo, como text/plain o image/jpeg)

En otras palabras files es la propiedad del <input type="file">. Es una colección (parecida a un array) llamada FileList. Dentro de files están los objetos individuales de tipo File.

Lo que no tienen es una propiedad que permita acceder al contenido del archivo. Acceder a eso es un poco más complicado. Para leerlo se usa FileReader, porque la lectura puede tardar y se maneja de forma asíncrona para no bloquear la interfaz.

<input type="file" multiple>

let input = document.querySelector("input");
input.addEventListener("change", () => {
    for (let file of Array.from(input.files)) {
    let reader = new FileReader();
    reader.addEventListener("load", () => {
        console.log("El archivo", file.name, "comienza con",
        reader.result.slice(0, 20));
    });
    reader.readAsText(file);
    }
});

La lectura de un archivo se realiza creando un objeto FileReader, registrando un controlador de eventos load para el y llamando a su metodo readAsText dandole el archivo que queremos leer.Cuando termina, el contenido está en reader.result. También existe el evento "error" si algo falla, y el error queda en reader.error.

ALMACENANDO DATOS DEL LADO DEL CLIENTE

El objeto localStorage se puede utilizar para almacenar datos de una manera que sobrevivan a las recargas de pagina. Te permite guardar valores de cadena bajo nombres.

localStorage.setItem("nombre_animal","Loro")
console.log(localStorage.getItem("nombre_animal"))

Un valor en localStorage permanecen hasta que se sobrescribe, se elimina con removeItem o el usuario elimina sus datos locales.

Existe ptrp objeto similar al localStorage, llamado sessionStorage. La diferencia es que este ultimo seolvida al final de cada sesion, es decir cada vez que el navegador se cierra.
